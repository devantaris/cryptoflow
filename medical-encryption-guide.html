Scene 05 / The Threat Model

What Could Go Wrong?

Three real-world failures. Click to simulate each.

💀 Wrong Diagnosis

Patient A has a tumor. Patient B has a migraine. Swap the reports. Without binding, the system accepts the wrong pairing. Doctor orders unnecessary surgery.

🕵️ Silent Edit

Hacker changes dosage from 10mg to 100mg in metadata. No tamper-evident seal means the system accepts it. Tenfold overdose administered.

🎭 Identity Swap

Insider swaps patient info on a celebrity's scan. Scan and report still match, so basic checks pass. Medical record now belongs to the wrong person.

Reference

The Glossary

One sentence each. No jargon.

🔐 Encryption

Scrambling information with a mathematical lock so only someone with the right key can read it.

🔑 Key

A very long, random password that tells the lock exactly how to scramble and unscramble the data.

🏛️ AES-256

A specific, battle-tested lock design used by banks and governments; the '256' means the key is enormously long.

🎲 IV / Nonce

A one-time random number mixed into the lock so encrypting the same file twice produces completely different output.

👆 Hash

A digital fingerprint: a short, unique code generated from a file. Change one bit, and the fingerprint becomes totally different.

🔗 Binding Hash

A fingerprint computed across multiple files together, then embedded into each one, so they are cryptographically welded together.

🕵️ Tamper-Evident

A property that makes it obvious if someone tried to open, change, or swap a file — like a broken wax seal.

📦 Ciphertext

The scrambled, unreadable output of encryption — what your file looks like while it's locked in the box.

✉️ Envelope / Bundle

The final package containing all encrypted files and binding information, ready to send through the network.
